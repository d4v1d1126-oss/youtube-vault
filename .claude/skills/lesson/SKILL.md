# /lesson <URL> — from ONE YouTube video to a study note in Obsidian

Goal: the reader can **study from the note without going back to the video**, and the vault grows as an organised library, not a pile of generated files. Priorities: **fidelity > usefulness for learning > quality > quantity**.

The channel, the vault folder, the note language and the limits all come from `vault/vault.config.json`. Read it once at the start if you need the author's name or the language.

## Core rules

- **One video per run.** `/lesson <URL>` processes that URL completely and stops. Do not start another video in the same context: the next one happens after `/clear` with another `/lesson <URL>`. With no argument, or with several URLs: ask for a single URL and stop.
- The transcript is **temporary working material** (to understand, to locate quotes, timestamps and concepts). **No transcript is ever saved into the vault.**
- Do not ask for intermediate confirmations; do stop and say so if something essential is missing (no subtitles, video already processed).
- Write the note in the **language configured in `vault.config.json`** (`language`), which should be the language the channel speaks.

## Paths (relative to the repository root, which is Claude Code's cwd)

- Script: `vault/vault.py` → always run it as `uv run vault/vault.py <cmd>`
- Topic vocabulary: `vault/topics.md`
- Temporary workspace: `vault/work/<video_id>/` (deleted whole by `finish`)
- Vault: the folder named by `vault_dir` in the config
  - `<Lessons>/<Short name>.md` ← the study note
  - `<Concepts>/<Topic>.md` ← only important, reusable concepts
  - `<Attachments>/<video_id>/<video_id>_mm-ss.jpg` ← screenshots
  - the index note ← regenerated by the script; never edit it by hand

## Procedure

### 1. Get the material
```
uv run vault/vault.py fetch "<URL>"
```
- `ALREADY PROCESSED` (exit 2): report the name of the existing note and **stop**. Only rebuild if the user explicitly asks (`--force`, after deleting the note and `<Attachments>/<id>`).
- `ERROR: the video has no subtitles`: report it and stop. Never invent a transcript.
- Produces in `vault/work/<id>/`: `meta.json`, `transcript_raw.md` (~60-word blocks, one line per block: `[mm:ss] text`), `words.json`, `sheets/sheet_NN.jpg` (contact sheets). At the end it prints the **topic vocabulary** and the **catalog of existing notes and concepts** (name and topics).
- **Do not open `meta.json`**: it holds the whole YouTube description and eats context. Title, channel, date and duration are already in the `=== SUMMARY ===` block that `fetch` prints.
- The catalog no longer carries summaries. When unsure whether a note is a linking candidate, read only that one: `grep "^summary:" "<vault>/<Lessons>/<Name>.md"` (or `^resumen:` when the language is Spanish).

### 2. Read everything
- All of `transcript_raw.md` with Read. It is the only source for what the speaker says.
- **Every** contact sheet with Read (images). Labels: `#id  mm:ss  (seconds on screen xrepetitions) [T]`; `[T]` = graphic/text card. One criterion only: does it help someone study without the video?

### 3. Analyse before writing
Identify: the central idea; the **real structure of the video** (blocks/steps as the speaker presents them, not as YouTube names them); concepts with a name of their own; examples; cause→effect arguments; quotes, studies, books; memorable lines; ASR doubts (names, numbers, nonsense phrases). In interviews: keep straight who says what (host vs. guest).

### 4. Choose screenshots: 0–6, each with a concrete job or none at all
Include one ONLY if it does a job: makes an idea understandable, demonstrates something explained, preserves a slide/whiteboard/screen, or keeps a reference (book, author, literal quote, graph, list, diagram). Every screenshot must be explainable in one line ("shows X"). If that line would be "the title of the step" or "the speaker talking", it does **not** go in.
- NO: shots of the person, b-roll, icon-only cards or cards that merely repeat a heading, fades, two screenshots saying the same thing, screenshots "out of obligation".
- **0 is valid** and common (interviews usually give 0–2). The cap is 6; `check` fails above it.
```
uv run vault/vault.py pick <video_id> 3,7,12
```
Returns the embeds `![[<video_id>_mm-ss.jpg]]`. Every screenshot copied must be used in the note (check fails on orphans). To inspect a candidate at full resolution before deciding: Read `vault/work/<video_id>/frames/cand_NNN.jpg`.

**Manual capture** (a whiteboard or screen whose complete state never appears in the contact sheets): when the transcript says "as you can see in the graph", dictates a list, and no candidate shows it, capture that exact moment (deduced from the transcript) **before `finish`**:
```
uv run vault/vault.py grab <video_id> 02:59
```

### 5. Timestamps (only the necessary ones)
Always `[mm:ss](https://youtu.be/<id>?t=<seconds>)`. These get a timestamp:
- the start of each block/section in *Structure* and of each *Main concept* (the block timestamp from `transcript_raw.md` is enough — it locates the start within about half a minute; no need for `quote`);
- screenshots (the timestamp comes from `pick`/`grab`);
- the **3–5 genuinely memorable literal quotes** of the note: only for those run
```
uv run vault/vault.py quote <video_id> "first words of the sentence"
```
Do not hunt exact timestamps for every claim, explanation or secondary sentence, and do not verify one just to back a secondary sentence: ordinary text can carry no timestamp, or the block's.

### 6. Write the note
`<vault>/<Lessons>/<Short name>.md`. Short name = a teaching title, no clickbait, ≤ 60 characters, without `: # ^ [ ] | \ / * ? " < >`. For the exact template in the configured language:
```
uv run vault/vault.py template
```
The note should feel like: "I watched this video, I understood what mattered, and here it is, organised for study."

Fidelity rules (non-negotiable):
- Plain text and `> [!quote]` = what the speaker says (faithful paraphrase, or a literal quote with a timestamp). Attribute precisely: if they say "science calls it X", write that, not "the speaker calls it X".
- `> [!info]` = my clarification. Never in plain text. Only when it is needed to prevent a confusion (a term, a reference, an ASR error); no broad outside research to enrich the note. If a reference is not needed to follow the content, marking it `[?]` is enough.
- `> [!tip]` = my connection or inference.
- Never invent data, studies, figures or quotes. What the speaker cites goes in as-is, and in *Links and sources* as "cited by the speaker; not verified".
- ASR doubts affecting a name or a figure: write the most likely reconstruction and mark it `[?]` in the note.
- Each screenshot goes **inside the section where it helps understand something**, with the line "*Screenshot [mm:ss](...): shows …*".
- **No redundancy**: an idea is explained once. *Key ideas* are short lines to memorise (≤ 10), not a second summary. Do not add sections beyond the template.
- **Questions and answers**: at most 7; only the ones that most help to study, remember or apply the content. Do not try to cover every point of the video with a question.
- **Topics**: 3–6 from `vault/topics.md`, exactly as written there. Add a new topic to `topics.md` (with a definition) ONLY if it recurs across the channel; otherwise use the closest existing one.
- Skip sponsor reads and promo segments. They are not study content.

### 7. Concept notes (0–2 per video; usually 0)
Create `<Concepts>/<Topic>.md` (name = a topic from the vocabulary, capitalised) only if the concept meets **all three**:
1. It really matters for understanding this video (an idea with a name of its own that the speaker defines or uses as a frame).
2. It is reusable beyond this video (it will show up in others, or already appears in ≥ 2 notes).
3. It earns a standalone note: it adds something the note itself does not explain better.

Prefer **updating** an existing one (adding this video's nuance under "What X says", with a link and timestamp) over creating another. Do not force it: 0 concepts is normal. The script maintains only the automatic "Lessons that cover it" section.

### 8. Link, check, finish
- *Links and sources*: `[[Name]]` only with a real relationship and one line of why; add the reverse link in the related note (just that line). If there is none: say so plainly.
- Run and fix until there are 0 errors:
```
uv run vault/vault.py check <video_id>
uv run vault/vault.py finish <video_id>
```
`finish` = check + deletes `vault/work/<video_id>` entirely (video, frames, sheets, subtitles, temporary transcript) + rebuilds the index and the automatic concept sections. If check reports errors, finish does not clean up: fix and repeat.

### 9. Report (short) and close
Path of the note; number of screenshots and what each shows; concepts created/updated (or "none"); notes linked; `[?]` doubts; check warnings. End with: **"This video is done. Run `/clear` before the next `/lesson <URL>`."** Do not continue with another video.

## Limits (anti-bloat)
| What | Limit |
|---|---|
| Notes per video | 1 study note + max. 2 concept notes (only if they meet all 3 conditions) |
| Screenshots | 0–6, each with a concrete job; never decorative, never repeated |
| Topics | 3–6 from the vocabulary |
| Key ideas | ≤ 10 |
| Questions and answers | ≤ 7, the most valuable for study/recall/application |
| Timestamps | section and concept starts, screenshots, and 3–5 memorable quotes; not one per sentence |
| `[!info]` | only to prevent confusion (term, reference, ASR); no outside research |
| Sections | only the 6 of the template |
| Repeated content | an idea is explained once |
